## Completed

- **Step 1 (#316, merged).** `src/core/bindings.ts`: every action with its
  Stardew default key, rebind, swap, reset, reserved keys (Esc, Enter, arrows,
  F1 to F12), `keyLabel`, `chooseProfile` and the settings record with a safe
  field by field parse. `browserSettingsStore` in `src/scenes/storage.ts`
  (`beaver-valley-settings`), and `loadDeviceSettings()` reads
  `pointer: coarse` on first run. 17 new tests.
- **Step 2 (this PR).** `src/scenes/controls.ts` now holds a `Controls`
  interface, a desktop profile (keyboard through the bindings, no pointer
  reads) and a touch profile (the stick, no keyboard). `FarmScene` passes
  intents and names no key. The HUD hides the Use, Eat, Skills and Row buttons
  and the debug button on desktop, and builds its hint from the bindings.
  `WitchWalkScene` uses the same factory.
- **Default keys are now Stardew's:** C use, Tab next slot, Left Shift next row,
  1 to 0, minus and equals pick a slot, F eat, K skills, Z end the day.
  Space, Q and E no longer do anything in the world. The Action (X) and menu (E)
  keys are bound but have no behaviour yet.
- **Playtests.** `launch` sets the profile in `localStorage` before the page
  loads (`profile` option, desktop by default, touch for `touch.mjs`). Scripts
  use C for use in the world and Tab for the next slot. Space stays in the shop
  and bin, where it is a menu key. `bin`, `wood` and `touch` ran with no findings. `expert` shows only
  "script error: could not reach X" findings (the bot stops one tile short of a
  target). The same run on `main` shows them too, so they are not new, but the
  branch had a few more (8 against 5 at similar days) and got less far in the
  same time. Not proven equal. See Risks.
- **Note 45** marked steps 1 and 2 done, and gained the right-click and
  context menu notes.
