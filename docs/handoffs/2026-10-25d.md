# Session Handoff: 2026-10-25 (fourth session)

## Summary

Built WP2 (#53). The scene now owns one `GameState`, shows a HUD and a toolbar,
and the player can dig, plant, water, harvest and forage with visible results.
What is left is a check on the tablet, then WP3 and the other work packages.

## Completed

- PR #73: the scene reads one `GameState` from the game registry, so it survives
  map changes (day and money no longer travel in scene restart data).
  `src/core/toolbar.ts` holds the toolbar model: hoe, can, hand, then the 12
  backpack slots, plus `startGame()` (15 parsnip seeds). `src/scenes/hud.ts`
  draws the status, toolbar and a Use button. Touches on the toolbar do not
  start the move stick.
- PR #74: `src/core/tools.ts` (`useHeld`, `reasonText`) maps the held slot to
  `till`, `water`, `plant`, `harvest` or `forage`. Space or Use acts on the
  facing tile. The scene draws plots, growth stages, ripe crops and forage
  spots as flat shapes. Failures show a message. Running out of energy ends
  the day through the pass-out rule.
- 114 tests, `npm run check` passes.

## Current state

  water, sleep four days, harvest, with the core's energy amounts. Not checked
  on the SM-T500.
- #53 is still open on purpose: its last acceptance item (touch on a real
  tablet) is unchecked. Nothing carries `next-payoff`.
- Controls: Space uses, Z sleeps, 1 to 9 and Q/E pick a toolbar slot, tapping a
  slot works too. Only 9 slots have number keys.
- Plots and forage are not stored per map, so tools only act on a map with soil
  (the farm). Fix this when a second farmable map exists.
- The debug hook `window.farmDebug()` also returns energy, plot count, seeds,
  harvested count, message and day (dev build only).
- Still missing: shop and selling (WP4), hall (WP5), end screen, saving from
  the scene, real art.
